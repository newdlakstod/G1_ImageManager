# 갤럭시 이미지 관리 앱 — 설계 문서

날짜: 2026-11-16
상태: 승인됨 (구현 계획 단계로 진행)

## 1. 개요

갤럭시 스마트폰(One UI)에서 동작하는 네이티브 안드로이드 앱. 카드 스와이프 방식으로
사진을 빠르게 정리(즐겨찾기 / 삭제 / 폴더 이동)하고, 유사·중복 사진을 자동으로 찾아
비교·정리할 수 있게 한다. 개인/가족용 사이드로드 배포 (Play 스토어 배포 계획 없음).

## 2. 기술 스택 및 아키텍처

- Kotlin + Jetpack Compose (UI), MVVM (ViewModel + StateFlow)
- 이미지 로딩: Coil / 리스트: Paging3
- Room DB: 앱 보조 데이터(해시 캐시, 중복 그룹 캐시, 폴더 정의)만 저장
- minSdk 30 (Android 11 / One UI 3.1+)

### 핵심 원칙: 즐겨찾기·삭제는 MediaStore에 위임

- **즐겨찾기** → `MediaStore`의 `IS_FAVORITE` 컬럼을 직접 갱신. 삼성 갤러리의
  "즐겨찾는 항목"과 즉시 동기화됨 (별도 동기화 로직 불필요).
- **삭제** → 커스텀 휴지통을 만들지 않고 `MediaStore.createTrashRequest()` 사용.
  OS가 30일 보관/복원을 전담하며, 삼성 갤러리 "최근 삭제" 폴더에서도 동일하게
  보이고 복원된다.
- 이 설계로 즐겨찾기/삭제 상태가 갤러리 앱과 항상 일치하며, 앱이 자체 상태를
  들고 있다가 어긋나는 문제를 원천 차단한다.

## 3. 화면 구성

### 3.1 메인 화면 — 카드 스와이프

사진 한 장을 전체화면 카드로 보여주고 제스처로 처리한다 (Slidebox 앱의 인터랙션을
참고):

| 제스처 | 동작 |
|---|---|
| 위로 스와이프 | 휴지통으로 이동 (`createTrashRequest`) |
| 아래로 스와이프 | 현재 선택된 폴더(파일함)로 이동 |
| 좌/우 스와이프 | 다음/이전 사진으로 이동 (파기 동작 없음, 순수 탐색) |
| 길게 누르기 | 즐겨찾기 토글 (`IS_FAVORITE`), 카드에 하트 표시 |

화면 상단에는 "현재 대상 폴더"가 칩으로 표시되며, 탭하면 폴더를 변경하거나
새로 만들 수 있다 (Slidebox의 "pile" 개념).

### 3.2 보조 탭

- **그리드** — 전체 사진 썸네일 그리드 (Paging3)
- **즐겨찾기** — `IS_FAVORITE=1`만 필터링한 그리드
- **유사 사진** — pHash로 자동 묶인 그룹을 카드 리스트로 표시
- **폴더함** — 사용자가 만든 폴더 목록 및 각 폴더 내용

### 3.3 비교 화면

유사 사진 탭에서 그룹을 선택하면, 그 그룹에 속한 사진들만 모아 카드 스와이프
화면으로 진입한다. 그룹 내에서도 동일한 제스처(위/아래/좌우/롱프레스)를 사용한다.

## 4. 유사 사진 자동 감지

### 4.1 해시 계산

- 사진마다 dHash(difference hash) 계산: 9×8 흑백 리사이즈 → 인접 픽셀 밝기 비교
  → 64비트 해시값
- Room에 캐시: `PhotoHash(mediaId, dateModified, hash)` — `dateModified`가 바뀐
  사진만 재계산

### 4.2 그룹핑

- 해시 간 해밍 거리(Hamming distance) ≤ 임계값(기본 10/64)이면 "유사"로 판정
- O(n²) 비교를 피하기 위해 해시 상위 비트로 버킷을 먼저 나누고, 같은 버킷
  안에서만 정밀 비교
- 유사 판정된 사진들은 union-find로 그룹화, `DuplicateGroup(groupId, mediaIds,
  computedAt)`로 캐시

### 4.3 스캔 트리거

- 자동 백그라운드 스캔 없음. 유사 사진 탭 진입 시 또는 사용자가 "다시 스캔"을
  누를 때 온디맨드 실행
- 캐시에 없는 mediaId만 증분 계산

## 5. 데이터 모델 (Room)

```
PhotoHash(mediaId PK, dateModified, hash: Long)
DuplicateGroup(groupId PK, mediaIds: List<Long>, computedAt)
Pile(pileId PK, name, folderRelativePath, createdAt)
```

실제 사진 파일, 즐겨찾기 상태, 삭제 상태는 MediaStore가 유일한 소스이며 앱 DB에
중복 저장하지 않는다.

### 향후 확장 (이번 스펙 범위 아님)

- 별 5개 중요도 평가 기능 요청이 있었으나, 복잡도를 고려해 이번 구현 범위에서
  제외. 추후 `PhotoRating(mediaId PK, rating: Int)` 보조 테이블을 추가하는
  방식으로 기존 스키마 변경 없이 확장 가능하도록 설계되어 있음.

## 6. 권한

- `READ_MEDIA_IMAGES` (API 33+) — 최초 실행 시 런타임 요청
- `MANAGE_EXTERNAL_STORAGE` (모든 파일 접근) — 폴더 이동을 확인창 없이 즉시
  처리하기 위해 요청. Play 스토어 배포가 아니므로 정책 제약 없음. 일반 런타임
  권한 다이얼로그가 아닌 설정 앱의 별도 화면으로 사용자를 안내해야 함.
- 거부 시 폴백: 즐겨찾기/삭제는 시스템 확인창 방식으로 동작 가능하나, 폴더
  이동은 매번 확인창이 뜨는 형태로 저하됨 (기능 자체는 유지).

## 7. 에러 처리

- 권한 거부 → 안내 화면 + 설정 바로가기 버튼
- 스와이프 중 삭제/이동 실패 (예: 파일이 이미 다른 앱에서 삭제됨) → 토스트 안내,
  카드 스택에서 자동 제외, 크래시 없이 다음 카드로 진행
- 해시 계산 중 손상된 이미지 → 해당 사진만 스킵하고 로그, 스캔 전체는 계속 진행
- 폴더 이동 대상 폴더가 삭제된 상태로 스와이프 다운 → "폴더 선택" 시트 자동 표시

## 8. 테스트 전략

- dHash / 해밍거리 / union-find 그룹핑 로직 → 순수 Kotlin 유닛 테스트 (고정
  테스트 이미지로 예상 그룹 검증)
- Room 캐시 무효화(= dateModified 변경 시 재계산) → 유닛 테스트
- MediaStore 연동(즐겨찾기 토글, 트래시, 폴더 이동) → 실기기/에뮬레이터
  계측 테스트 (Robolectric으로는 한계가 있어 실제 디바이스 검증 필요)
- 카드 스와이프 제스처 인식 → Compose UI 테스트로 제스처 시뮬레이션 검증

## 9. 범위 밖 (명시적으로 제외)

- iOS / 크로스플랫폼 지원
