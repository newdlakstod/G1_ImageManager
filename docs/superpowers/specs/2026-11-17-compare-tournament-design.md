# 비교 화면 재설계: 토너먼트 방식 (2026-11-17)

## 목적
그리드에서 여러 장을 선택해 "더 나은 한 장"을 고르는 화면을 이상형 월드컵 방식으로 바꾼다.
기존 v0.7.0의 "남길 사진 탭 → 나머지 삭제" 화면을 대체한다.
핵심 사용 사례는 연속 촬영한 비슷한 사진의 **흐림/초점 비교**이므로 확대 비교가 필수다.

## 결정 사항
- 비교 장수는 상황마다 다름 (2장~수십 장) → 항상 2장씩 비교하는 토너먼트 방식.
- 첫 주 이미지 = 그리드에서 **먼저 선택한 사진**.
- 도전자의 "우선" 선택 시 밀려난 기존 주 이미지는 **보류**.
- 실제 삭제는 **끝날 때 한 번에** (시스템 확인창 1회). 중간에 나가면 아무것도 삭제되지 않는다.
- 보류 사진과 최종 주 이미지는 마지막에 그대로 남긴다 (별도 처리 없음).

## 화면
- 항상 이미지 2장. 가로 모드: 좌(주)/우(도전자). 세로 모드: 상(주)/하(도전자).
- 각 이미지에 `주` / `도전` 라벨. 상단에 진행 표시 "n / 전체 도전자 수".
- 도전자 쪽에 버튼 3개: **삭제 / 보류 / 우선**. 추가로 "이전으로" 버튼.
- 화면 회전 시 진행 상태 유지 (ViewModel에 상태 보관).

## 동기 확대
- 한 이미지를 핀치/드래그하면 다른 이미지도 같은 배율·같은 상대 위치로 함께 움직인다.
- 도전자가 바뀌면 배율/이동은 초기화.
- 배율 1~6배. 배율 1일 때는 이동하지 않는다.

## 진행 규칙 (순수 로직, `CompareSession`)
상태: `main: Photo`, `queue: List<Photo>`(남은 도전자), `deleted`, `held`, 이전 상태 스택.
- 시작: photos[0] = main, 나머지 = queue.
- `challenger` = queue 맨 앞. queue가 비면 완료.
- `delete()`: challenger → deleted, 다음 도전자.
- `hold()`: challenger → held, 다음 도전자.
- `promote()`: main → held, challenger → main, 다음 도전자.
- `undo()`: 마지막 동작 취소 (모든 동작은 상태 스냅샷 스택으로 되돌린다).
- 사진이 1장 이하면 비교 화면 진입 불가 (그리드의 "비교" 버튼은 2장 이상일 때만 활성, 기존 유지).

## 마무리
- 완료 시 요약: 최종 주 이미지(남김) 1장, 보류 N장, 삭제 M장.
- 버튼 "삭제 M장 휴지통으로 보내기": `MediaStore.createTrashRequest` 시스템 확인창 1회
  → 성공하면 이전 화면으로 복귀. M = 0이면 "완료" 버튼만 표시.
- 확인창 취소 시 요약 화면에 머무른다 (다시 시도 가능).

## 구성 요소
- `CompareSession` (순수 Kotlin, `ui/compare/`): 위 진행 규칙. JVM 유닛 테스트 대상.
- `CompareViewModel`: `CompareSession` 상태를 `StateFlow`로 노출, 회전 시 유지.
- `ComparisonScreen`: 레이아웃(가로/세로 분기), 동기 확대 제스처, 버튼, 요약 화면.
- `AppNavHost`: 기존 `compare/{mediaIds}` 라우트 유지. ids 순서 = 선택 순서
  (그리드의 `selectedIds`는 Set이지만 추가 순서를 유지하므로 `toList()`로 충분.
  단 `listByIds`는 SQL `IN` 조회라 순서가 보장되지 않으므로, 네비게이션에서 ids 순서대로 재정렬한다.)

## 테스트
- `CompareSessionTest`: delete/hold/promote 후 상태, 완료 판정, undo(여러 번), 2장/1장 경계.
- 동기 확대와 레이아웃은 수동 확인 (실기기).

## 범위 밖
- 보류 사진 재심사 화면, 즐겨찾기 지정, 파일 정보(용량/해상도) 표시.
